# The architecture lessons hiding in 337,000 stars

**The most important finding from six months of individual-built AI agent systems is not any single project — it's a convergent architectural pattern emerging independently across every successful system.** From Karpathy's 630-line autoresearch to a 25-agent financial system generating 22% returns, the winners all discovered the same thing: the specification layer IS the system. The model is interchangeable. The harness, the evaluation loop, and the memory architecture determine everything. This report extracts the patterns that matter for building the Keystone Intelligence Engine, identifies what failed and why, and provides concrete architectural decisions backed by production evidence from October 2025 through March 2026.

---

## The six projects that actually matter and what they prove

**OpenClaw** (337K stars, up from the reported 210K) is the cautionary tale. Peter Steinberger's autonomous always-on agent — browsing web, filling forms, controlling smart homes, writing its own skills — demonstrated both the ceiling and floor of open agent ecosystems simultaneously. The architecture is a long-running Node.js service with a WebSocket control plane at `ws://127.0.0.1:18789`, using SKILL.md markdown files as the universal skill format. The self-modifying capability is real: the agent sits in its own source code and can prompt-modify itself. But the **ClawHavoc supply chain attack** planted 800+ malicious skills across ClawHub (~20% of the entire registry), Cisco found 26% of 31,000 analyzed skills contained vulnerabilities, and CVE-2026-25253 proved that visiting a single malicious webpage could hijack any of the **135,000+ exposed instances** found on the public internet. Simon Willison's "lethal trifecta" — private data access + untrusted content exposure + external communication — was proven correct at scale. For Keystone: open skill ecosystems without cryptographic vetting are supply chain attack surfaces. Period. Popularity-based trust rankings were gamed within weeks.

**Superpowers** (120K stars) by Jesse Vincent is the strongest evidence that specification quality determines output quality. The mandatory workflow forces agents through brainstorming → git worktree isolation → precise planning → subagent execution → verification → systematic debugging. Plans are written as if for "an enthusiastic junior engineer with poor taste, no judgment, no project context, and an aversion to testing." This means **the cognitive work happens entirely in the planning phase**; implementation becomes mechanical. The proof: Superpowers works identically across Claude Code, Cursor, Codex CLI, OpenCode, Gemini CLI, Qwen Code, Goose CLI, and Auggie. If the implementing model were doing real cognitive work, platform-switching would degrade quality. It doesn't. Vincent also discovered that **subagent review loops doubled execution time (~25 min overhead) without measurably improving plan quality** — regression testing across 5 versions × 5 trials showed identical quality scores. An inline self-review checklist catching 3-5 bugs per run in ~30 seconds replaced the entire review layer at 1/50th the cost.

**Karpathy's autoresearch** (56.6K stars, up significantly from the reported 42K) proved the ratchet loop works. Three files: `prepare.py` (fixed evaluation), `train.py` (agent's sandbox, 630 lines), `program.md` (human's research direction). The agent reads the current state plus git history plus a results.tsv log, forms a hypothesis, modifies the sandbox file, runs a 5-minute experiment, and either commits (improvement) or git-resets (no improvement). Karpathy's runs on 8×H100: 276 experiments, 29 kept, steady downward loss. Shopify CEO Tobi Lütke: **19% validation improvement from 37 experiments**, then separately **53% faster rendering from 93 automated commits**. The 18% keep rate is consistent across independent reproductions. But the ratchet has a known failure mode documented in GitHub Issue #22: the agent cycles through minor variations of whatever worked last, trapped in local search. It cannot temporarily worsen performance to set up a larger gain. No one has reported it inventing a novel architecture — improvements are incremental parameter tweaks. For Keystone: the autoresearch loop is the most directly applicable pattern, but needs a population-based variant (like AIDE's tree-search) to escape local optima.

**garrytan/gstack** (45.7K stars) encodes Y Combinator's sprint philosophy as agent skills. The 28 Markdown-based role prompts constrain Claude to one organizational role per interaction — CEO review, engineering review, design review, security officer, QA. The genuinely novel piece is the **persistent Chromium daemon**: a Playwright-based headless browser running as an HTTP daemon on localhost with sub-second latency and cookie import from real browsers via macOS Keychain decryption. The `/autoplan` skill chains CEO → design → eng review automatically and surfaces only "taste decisions" to humans. Garry Tan claims 600K+ lines of production code in 60 days. For Keystone: the role-isolation pattern (one agent, one organizational perspective) and the "taste decision" routing (only escalate subjective judgments) are directly applicable to research agent design.

**everything-claude-code** (112K stars) by Affaan Mustafa contains the most architecturally novel component found in this research: the **instinct-to-skill evolution system**. Hooks capture every tool call and outcome at 100% reliability. A background Haiku agent detects patterns in these observations and creates "instincts" — atomic YAML+Markdown behaviors with confidence scores (0.3–0.9), domain tags, evidence trails, and confidence decay when contradicted. The `/evolve` command clusters related instincts into full skills. Version 2.1 adds project-scoped instincts that can promote to global scope. The **AgentShield** security scanner (1,282 tests, 98% coverage, 102 static analysis rules) uses a three-agent red-team/blue-team/auditor pipeline. For Keystone: the instinct-to-skill pipeline is the best existing implementation of agent self-improvement through observation — directly adaptable for research agents that learn which approaches work for which query types.

**Chris Worsey's ATLAS** (650+ stars) is the most relevant architecture for Keystone because it's a production multi-agent system with published performance metrics. The 4-layer, 25-agent system generated **+22% returns over 173 days at $20/month** (self-reported, not independently audited). Layer 1: 10 macro agents (central bank policy, geopolitical risk, commodities, etc.). Layer 2: 7 sector desk agents. Layer 3: 4 "superinvestor" personas (Druckenmiller for macro/momentum, Ackman for quality compounders, etc.). Layer 4: 4 decision agents including an adversarial Chief Risk Officer. The Darwinian prompt evolution mechanism scores every agent by rolling **Sharpe ratio**, identifies the worst performer, rewrites its prompt, tests for 5 trading days, then keeps or reverts. Over 378 trading days: 54 modifications attempted, 16 survived (30% keep rate). The system's most important discovery: **it downweighted its own CIO (synthesis agent) to minimum weight (0.3)**. Worsey's conclusion — "the synthesis/decision layer is the bottleneck" — is the single most important architectural lesson for Keystone.

## The convergent pattern: SKILL.md and specification-as-system

Every successful project independently converged on **markdown-based instruction files** as the primary programming interface for agents. OpenClaw uses SKILL.md directories. Superpowers uses SKILL.md with mandatory workflows. Autoresearch uses program.md. gstack uses role-constrained .md files. Everything-claude-code uses YAML-frontmatter markdown for agents, skills, and commands. This isn't coincidence — it reflects a deep architectural truth: **the specification layer, not the model layer, determines system quality**. When Superpowers produces identical results across 8 platforms, it proves the model is commodity infrastructure. When ATLAS's synthesis agent gets downweighted to 0.3, it proves that even sophisticated orchestration can't compensate for weak specification.

For Keystone's six-layer pipeline, this means the planning and specification layer deserves **disproportionate engineering investment**. The 199-biotechnologies' claude-deep-research-skill (58 stars, but architecturally rich) provides the most detailed blueprint: an 8-phase pipeline running Scope → Plan → Retrieve (5-10 concurrent searches with "First Finish Search" adaptive quality thresholds) → Triangulate (3+ sources per claim) → Outline Refinement → Synthesize → Critique (8 automated validation checks with loop-back to retrieval if gaps found) → Package. The **critique loop-back to retrieval** — Phase 7 triggering additional targeted searches when gaps are detected — is self-healing research that Keystone should implement.

## What failed: the rejection library worth more than the success stories

**Subagent review loops are waste.** Superpowers' regression testing proved that dispatching a fresh agent to review plans added 25 minutes without improving quality. An inline self-review checklist achieved comparable defect detection in 30 seconds. The lesson: don't add agents to solve quality problems — add better specification to prevent them.

**Open skill ecosystems without vetting are malware distribution networks.** OpenClaw's ClawHavoc attack planted 800+ malicious skills. The "What Would Elon Do?" skill — gamed to #1 ranking, downloaded thousands of times — was functionally malware executing silent `curl` data exfiltration. Cisco's response (DefenseClaw with NVIDIA, open-source Skill Scanner) arrived 3+ months after the ecosystem launched. For Keystone: any skill/tool ecosystem needs cryptographic signing, sandboxed execution, and network-deny-by-default policies from day one.

**Single-lineage ratchets hit local optima.** Autoresearch's "one change at a time, keep or revert" constraint prevents exploring paths that get worse before getting better. The fork ecosystem already addresses this: WecoAI/AIDE uses tree-search instead of linear search, and HKUanDS/ClawTeam runs agent swarms for parallel GPU research. Karpathy himself acknowledges the limitation and envisions "SETI@home style" massive asynchronous collaboration — but Git's single-master-branch assumption is a bottleneck.

**LLM-as-judge error rates exceed 50%** without calibration. Galileo's 2026 research documents position bias, length bias, and agreeableness bias in automated evaluators. Multi-model consensus helps, but the gold standard remains calibrating against human judgment with a target of 0.80+ Spearman correlation using 100-200 expert-scored samples.

**The "orchestration bottleneck" is universal.** ATLAS discovered it empirically when its system downweighted the CIO. The MAESTRO framework (arxiv:2601.00481) confirmed that MAS architecture — not model selection or tool changes — is the dominant driver of system performance. Almost half of production multi-agent systems execute fewer than 5 steps before requiring human intervention. For Keystone: invest more in the orchestrator's specification quality than in adding more specialist agents.

## The evaluation stack that actually works in production

Anthropic's "Demystifying Evals for AI Agents" (January 9, 2026) established the production standard: a **three-tier grading stack**. Code-based graders (string matching, format validation, citation verification) handle L1 — fast, cheap, deterministic. Model-based graders (LLM-as-judge with calibrated rubrics) handle L2 — flexible but requiring calibration. Human graders handle L3 — expensive but essential for calibrating L2. The critical distinction Anthropic draws is between **capability evals** (what can the agent do? start at low pass rate, iterate upward) and **regression evals** (does it still work? maintain near 100%). Capability evals that reach high pass rates "graduate" to regression suites.

For Keystone's research outputs, the most actionable finding comes from the rejection sampling literature. The paper arxiv:2504.11343 shows that **simple rejection sampling** (generate N outputs, keep the best per a reward model) is competitive with GRPO and PPO for quality improvement — and far simpler to implement. The power comes from a specific mechanism: discarding prompts where all N outputs are incorrect, which implicitly filters for solvable problems. Applied to consulting research: generate 3 research drafts, score with domain-specific rubrics, keep the best. The 199-biotechnologies critique-loop-back pattern adds a second dimension: when the best of N still fails quality thresholds, trigger additional targeted retrieval rather than re-generating from the same information.

The **Generator-Reflector-Curator** pattern (from 47billion's 2026 research) provides a complete evaluation-to-memory feedback loop: the Generator produces output, the Reflector evaluates and refines it, and the Curator extracts learnings into a persistent playbook. Published results show **+10.6% on agent benchmarks without any model fine-tuning** — purely from better memory and evaluation loops.

## Memory architectures beyond vector search

The 199-biotechnologies' **Engram** MCP server represents the most sophisticated small-team memory implementation. It combines BM25 + ColBERT + Knowledge Graph for hybrid search, with Jina v5 semantic search achieving ~9ms/query on Apple Silicon via MLX Metal acceleration. The key innovation is **temporal memory decay**: important memories persist, trivial ones fade, and recall strengthens memories — modeled on human cognition rather than database paradigms. It achieves 80% on the LOCOMO benchmark for long-context memory evaluation. Multiple community reimplementations exist in Rust, Go, and TypeScript, validating the architecture.

A simpler but effective alternative is the **three-tier file-based memory pattern** documented across multiple production systems: Hot memory (~200 lines, loaded every session), Warm memory (topic-specific files loaded on demand), and Cold memory (compressed monthly archives). End-of-session triage promotes, archives, or discards. The insight: "Most agent frameworks treat memory as a storage problem. The failure is the agent doesn't control what it remembers." Vector retrieval surfaces what's semantically similar, not what's important right now.

LangGraph (now exceeding **100 million monthly framework downloads**) provides the most mature production infrastructure for trajectory storage. Its checkpointing system uses UUID v6 IDs with embedded timestamps, creating a linked-list checkpoint history that enables pause/resume, time-travel debugging, and state forking. Harrison Chase frames this as "context engineering" — bringing the right information in the right format to the LLM at the right time. The Deep Agents layer adds standardized sub-agent spawning, long-term memory, and a virtual filesystem. For trajectory storage specifically, LangGraph's architecture of immutable state checkpointed after every step, with deterministic replay capability, is the production standard.

## The autoresearch pattern applied beyond ML

Karpathy's ratchet loop has already been generalized far beyond ML training. The awesome-autoresearch repository catalogs applications to documentation SEO optimization, landing page conversion, marketing copy, prompt engineering, Lighthouse performance scores, bundle sizes, and build times. A Bitcoin price prediction variant ran 328 experiments and achieved **50.5% RMSE improvement**. The Vesuvius Challenge ran 4 agents 24/7 on ink detection models.

The most relevant variant for Keystone is **uditgoenka/autoresearch**, a Claude Code plugin that generalizes the loop to any quantifiable optimization. It adds **MAD-based confidence scoring** (Median Absolute Deviation) to distinguish real improvements from statistical noise — solving a problem the original autoresearch ignores. The pi-autoresearch extension adds a visual confidence indicator: ≥2× MAD = green (real improvement), 1-2× = yellow (possible noise), <1× = red (likely noise).

**Artemis** (TurinTech, arxiv:2512.09108) takes this further with population-based evolutionary optimization of entire agent configurations — not just prompts but tool descriptions, parameters, and workflow structures. Using semantically-aware genetic operators, it achieved **9.3% to 36.9% improvements** across 4 agent systems with statistical significance. The key architectural insight: treating the entire agent (prompt + tools + workflow) as an optimizable genome rather than hand-tuning individual components.

For Keystone's consulting research, the autoresearch pattern could work as follows: define a research quality metric (factual accuracy + source diversity + insight novelty + actionability, scored by calibrated LLM-as-judge), generate research outputs, keep improvements, revert regressions, and use the results.tsv log to guide the next iteration's approach. The key constraint: the evaluation function must be designed before the loop runs, and it must be calibrated against human expert judgment.

## What the hackathons revealed about who wins

The Anthropic "Built with Opus 4.6" hackathon (February 2026, 13,000 applicants, 500 accepted) produced the most important signal: **domain experts beat developers**. First place went to a California attorney who built a permit-processing automation in 6 days. Second place to a Brussels cardiologist. Third to a Ugandan road technician. None were professional developers. The lesson is that deep domain understanding of the problem being solved matters more than engineering sophistication of the agent architecture.

The Microsoft AI Agents Hackathon (18,000 registrants, 570 submissions) awarded Best Overall to **RiskWise**, a supply chain risk analysis system using multi-agent architecture for schedule variances, geopolitical events, labor conditions, tariffs, and logistics disruptions. This is the closest hackathon project to Keystone's consulting research use case — multi-perspective analysis of complex business questions with structured output.

Across all Q1 2026 hackathons, a pattern emerges: the winning projects are never the most technically complex. They are the ones with the **tightest problem definition and the clearest evaluation criteria**. This maps directly to the specification-as-system thesis.

## Concrete recommendations for Keystone's six-layer pipeline

Based on the full body of evidence, here are the architectural decisions with the strongest empirical support:

**Use LangGraph as the runtime layer.** It has 100M+ monthly downloads, production deployments at Klarna, Uber, J.P. Morgan, and BlackRock, and the only mature implementation of time-travel debugging and state forking for agent systems. The Deep Agents harness ("a prompt, tools, and subagents") maps cleanly to Keystone's pipeline. The checkpointing system provides durable execution that survives server restarts — non-negotiable for long-running research tasks.

**Implement the 199-bio 8-phase pipeline as the research agent skeleton.** Scope → Plan → Parallel Retrieve with First Finish Search → Triangulate → Outline → Synthesize → Critique with loop-back → Package. The FFS pattern (adaptive quality thresholds that determine when to stop searching) prevents both under-researching and over-researching. The critique loop-back to retrieval is the self-healing mechanism that makes research agents reliable.

**Steal ATLAS's 4-layer multi-perspective architecture.** Specialist agents (analogous to ATLAS's macro agents) feed into domain desk agents, which feed into methodology persona agents (McKinsey frameworks, first-principles analysis, design thinking — analogous to ATLAS's superinvestor personas), which feed into a synthesis layer. Apply dynamic weighting based on rolling quality scores. But heed the orchestration bottleneck warning: invest heavily in the synthesis layer's specification quality.

**Build the instinct-to-skill evolution loop from ECC.** Hook every tool call and outcome. Run a cheap background model to detect patterns. Create atomic instincts with confidence scores and decay. Cluster into skills via `/evolve`. This is the mechanism by which Keystone learns which research approaches work for which query types without human intervention.

**Adopt the three-tier evaluation stack.** L1: deterministic checks (format, citation existence, source diversity count). L2: calibrated LLM-as-judge scoring insight quality, accuracy, and actionability against 100-200 expert-scored samples targeting 0.80+ Spearman correlation. L3: periodic human spot-checks that recalibrate L2. Graduate capability evals to regression suites as they stabilize.

**Use the autoresearch ratchet for prompt evolution.** Score each research agent's output quality over a rolling window. Identify the worst performer. Rewrite its specification (not just its prompt — the full SKILL.md). Test for a defined period. Keep or revert via git. ATLAS's 30% keep rate on financial prompts provides a reasonable baseline expectation. Add MAD-based confidence scoring to filter noise.

**Implement three-tier memory, not just vector search.** Hot memory loaded every session (current project context, client preferences, recent findings). Warm memory loaded on demand (domain knowledge, methodology playbooks). Cold memory in compressed archives. End-of-session triage promotes or discards. Supplement with Engram-style temporal decay for the warm tier — memories that haven't been accessed fade, memories that get recalled strengthen.

## Conclusion

The most striking finding across six months of agent system development is how consistently the same patterns emerge independently. The specification layer dominates system quality. Open ecosystems without security primitives get compromised within weeks. Review loops add cost without improving quality — but critique-with-loop-back-to-retrieval does improve quality. Single-lineage optimization hits local optima; population-based search doesn't. Domain experts building agents outperform engineers building agents. And the synthesis/orchestration layer — not the specialist agents — is always the bottleneck.

The gap in the ecosystem that Keystone could fill is the missing connection between evaluation and memory. No production system yet implements a complete loop where research output evaluation signals update agent memory, which updates agent specification, which improves the next research output. The Generator-Reflector-Curator pattern achieves +10.6% from this loop in benchmarks, but no consulting research system has implemented it. The combination of ATLAS's Darwinian evolution, ECC's instinct-to-skill pipeline, and the 199-bio critique loop-back creates a closed self-improvement cycle that doesn't yet exist as an integrated system. Building that integration is Keystone's strategic opportunity.
